## Repository Overview

This is a fork of QMK firmware with Miryoku layout integration. It contains keyboard firmware for custom mechanical keyboards, currently configured for a Cantor split keyboard. The repository follows the Miryoku QMK development branch (`miryoku`) which provides an ergonomic, minimal, orthogonal keyboard layout.

## Build Commands

Build firmware for Cantor keyboards:
```bash
make cantor:default                    # Build cantor (VIA-enabled, basic layout)
make cantor_hr:default                 # Build cantor_hr (homerow mods + chordal hold)
make cantor:default:flash              # Build and flash
make cantor_hr:default:flash           # Build and flash cantor_hr
qmk compile -kb cantor_hr -km default  # Alternative using qmk CLI
qmk flash -kb cantor_hr -km default    # Alternative flash using qmk CLI
```

Build with Miryoku layout:
```bash
make crkbd:manna-harbour_miryoku       # Build Miryoku for crkbd
make cantor:manna-harbour_miryoku      # Build Miryoku for cantor
```

Build with alternative layout options:
```bash
make crkbd:manna-harbour_miryoku \
  MIRYOKU_ALPHAS=QWERTY \
  MIRYOKU_EXTRA=COLEMAKDH \
  MIRYOKU_NAV=INVERTEDT \
  MIRYOKU_CLIPBOARD=WIN \
  MIRYOKU_LAYERS=FLIP
```

Clean build artifacts:
```bash
make clean           # Delete .build/
make distclean       # Delete .build/ and *.bin, *.hex, *.uf2
```

## Key Architecture

### Keyboard Structure
Each keyboard lives in `keyboards/<name>/` with:
- `rules.mk` - Build options (features like VIA, split keyboard, serial driver)
- `config.h` - Hardware configuration (pins, communication settings)
- `info.json` - Keyboard metadata and layout definitions
- `keymaps/` - Directory containing keymap variants

### Miryoku Userspace
The Miryoku layout implementation lives in `users/manna-harbour_miryoku/`:
- `rules.mk` - Enables features: mouse keys, auto shift, tap dance, caps word
- `config.h` / `custom_config.h` - Layout configuration options
- `manna-harbour_miryoku.c` - The keymap definition
- `miryoku_babel/` - Layer definitions generated by Miryoku Babel

Miryoku maps a 10x4 layout (`LAYOUT_miryoku`) onto various keyboard physical layouts using C macros.

### Cantor Keyboard Variants

#### `keyboards/cantor/` — VIA-enabled basic layout
- Split keyboard with USART full-duplex serial communication
- VIA enabled for runtime keymap editing
- 6 dynamic keymap layers, mouse keys enabled
- Uses `LAYOUT_split_3x6_3` (3 rows × 6 columns per side + 3 thumb keys)

#### `keyboards/cantor_hr/` — Homerow mods with Chordal Hold (active development)
Custom layout built on the `cantor-hr-upgrade` branch. Key features:

**Homerow Mods (Timeless style, ZMK-inspired tuning):**
- Left: S=Ctrl, D=Alt, F=GUI | Right: J=GUI, K=Alt, L=Ctrl
- `TAPPING_TERM 280`, `QUICK_TAP_TERM 175`, `FLOW_TAP_TERM 150`
- Chordal Hold enabled for opposite-hand filtering (prevents misfires)

**6 Layers:**
- `_BASE` — QWERTY with homerow mods, Shift on thumb (SFT_SPC left, BSPC right)
- `_SYM` — Numbers (left) and symbols/brackets (right), accessed via right thumb
- `_EXT` — Navigation (arrows, PgUp/Dn, Home/End) and macOS shortcuts (Cmd+Z/X/C/V/S/A/T), accessed via left thumb
- `_FNC` — F1-F12 with one-shot mods on left homerow, accessed from EXT layer
- `_AERO` — Window management layer (Alt+number shortcuts, Shift+Alt variants), accessed via combo or from EXT
- `_SETT` — Settings: QK_BOOT (bootloader) and EE_CLR (EEPROM clear), accessed via combo

**Combos (COMBO_TERM 50):**
- U+I → `'`, I+O → `"`, Comma+Dot → `` ` ``, Dot+Slash → `~`
- M+Comma → `\`, M+Dot → `|`
- MO(_EXT)+Enter → AERO layer, Tab+MO(_EXT) → SETT layer

**Build features:** Combos enabled, LTO (Link-Time Optimization) enabled
**Hardware:** BlackPill F401, same pin layout as cantor, USART full-duplex split

## Flashing

Enter bootloader mode on Cantor:
1. **Bootmagic reset**: Hold top left (or top right for right side) key and plug in
2. **Physical buttons**: Hold BOOT0, press/release NRST, release BOOT0
3. **Keycode**: Press key mapped to `QK_BOOT`

## Branch Structure

- `miryoku` - Main branch with Miryoku integration
- `cantor-hr-upgrade` - Active development branch: custom cantor_hr keyboard with homerow mods, chordal hold, flow tap, combos, and 6-layer layout. Includes upstream QMK merge for Chordal Hold and Flow Tap support.
